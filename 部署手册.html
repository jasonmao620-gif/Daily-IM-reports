IM 每日简报 · 云端部署手册

目标：每天早上 7:00，手机微信自动收到一份中证1000 盘前简报。全程约 20 分钟，一次性配置，之后不用管。

先看懂：这件事由三块拼起来

① GitHub 仓库存放代码 + 存每天生成的网页
② GitHub ActionsGitHub 自己的免费服务器，每天 7 点自动跑一次
③ Server酱把结果推到你微信的中间人，免费

你不需要一直开着电脑，也不需要在电脑上装 Python。跑的机器是 GitHub 的，不花电费、不花服务器费。

为什么要 Public（公开）仓库？GitHub 免费账号的「网页托管（Pages）」只对公开仓库开放。报告里没有你的持仓、账户、身份信息，全是公开行情，公开没有隐私风险。所有密钥都存在 Secrets 里，不随代码公开。

1建一个仓库

  1. 浏览器打开 github.com，登录（没账号点 Sign up 注册）。
  2. 右上角 + 号 → New repository。
  3. 填写：
    • Repository name：im-daily（名字随便，记住即可）
    • 下面选 Public（这一步很关键，别选 Private）
    • 不要勾选 Add a README file（避免后面冲突）
  4. 点绿色按钮 Create repository。出现一个空仓库页面，先放着。

2把代码传上去 推荐用 GitHub Desktop

为什么不用网页拖拽：本项目里有一个隐藏文件夹 .github，定时任务的配置文件就藏在里面。网页上传时看不见它，很容易漏掉——漏了就会出现「定时任务根本没被创建」这种很难查的问题。用 GitHub Desktop 拖文件夹不会漏。

  1. 打开 GitHub Desktop → Sign in to GitHub.com → 浏览器里点授权 → 回到软件。
  2. 菜单 File → Add local repository…。
  3. 点 Choose…，选中本机的 cloud 文件夹，点 Add repository。
  4. 软件会提示这不是一个仓库，点提示里的 create a repository 链接。
    • Name 保持 cloud（或改成 im-daily）
    • Description 留空
    • 不要勾 Git ignore / License
    • 点 Create repository
  5. 左侧会出现一堆文件，底部 Summary 随便填 init，点 Commit to main。
  6. 顶部点 Publish repository，弹窗里把「Keep this code private」的勾去掉（必须去掉，否则 Pages 用不了），点 Publish repository。
完成后回到 GitHub 网页刷新，应该能看到 main.py、src、docs、.github 这些文件。看到 .github 就说明成功了——这是最容易漏的一个。

3打开网页托管（Pages）

  1. 在仓库页面点 Settings（顶部菜单，齿轮图标）。
  2. 左侧栏找到 Pages。
  3. Source 选 Deploy from a branch。
  4. Branch 选 main，右边文件夹选 /docs，点 Save。
  5. 等 1–2 分钟刷新页面，顶部会出现一行：
    Your site is live at https://jasonmao620-gif.github.io/Daily-IM-reports/
这个网址复制下来，下一步要用。注意结尾不要带斜杠，也不要带 index.html。

4填第一个设置：PAGES_BASE（现在可以跳过）

这一步已经改成自动推导了，不用再手动填。工作流会按 https://用户名.github.io/仓库名 这个确定规则自己算出来，算错的可能性比手填更低。只有当你要绑自己的域名时，才需要回来设这个变量。

下面保留原步骤，供绑域名时参考：让程序知道报告的网址，才能把「点开看全文」的链接放进微信。

  1. 仓库 Settings → 左侧 Secrets and variables → Actions。
  2. 点 Variables 标签（不是 Secrets）。
  3. 点 New repository variable。
  4. Name 填 PAGES_BASE；Value 填上一步那个网址，例如 https://mao.github.io/im-daily。
  5. 点 Add variable。

5拿一个 Server酱 的钥匙

  1. 手机微信打开扫一扫，电脑浏览器打开 sct.ftqq.com。
  2. 点 微信扫码登录，手机确认。
  3. 页面会显示一串以 SCT 开头的字符，这就是 SendKey，复制它。
免费版每天 5 条消息，我们每天只推 1 条，够用。以后想换通道（比如企业微信机器人、PushPlus），代码里已经预留了 PUSH_CHANNEL 开关。

6填第二个设置：PUSH_KEY

  1. 还是 Settings → Secrets and variables → Actions，这次点 Secrets 标签。
  2. 点 New repository secret。
  3. Name 填 PUSH_KEY；Secret 粘贴刚才那串 SCT…。
  4. 点 Add secret。
Secrets 存进去之后连你自己都看不到原文，只能覆盖重填，这是正常的。它就是给密码类信息用的位置。

7手动跑一次，验证通了

  1. 仓库顶部点 Actions。
  2. 左侧列表点 IM 中证1000 盘前简报（早7点）。
  3. 右边有个灰色提示条写着「This workflow has a workflow_dispatch event trigger」，点右侧的 Run workflow 按钮 → 再点绿色 Run workflow。
  4. 等 10 秒刷新，会出现一条正在跑的记录，点进去能看到每一步的日志。
  5. 全部变绿勾后，手机微信应该收到消息（Server酱 服务号）。
如果 Actions 左边列表里找不到这个工作流，说明第 2 步的 .github 文件夹没传上去。回 GitHub Desktop 看一下文件列表里有没有 .github，没有就从原文件夹重新拖进去再提交。

8确认定时：每天早 7 点

定时规则已经写在配置文件里了，你不需要改。它长这样：

# 早 7:00 北京时间 = 前一天 23:00 UTC（中国无夏令时，全年 UTC+8）
- cron: '0 23 * * 0-4'

为什么是 0 23 而不是 0 7：GitHub 的钟走的是 UTC 世界时，比北京晚 8 小时。

北京时间UTC 时间cron 里的星期
周一 07:00周日 23:000（周日）
周二 07:00周一 23:001
周三 07:00周二 23:002
周四 07:00周三 23:003
周五 07:00周四 23:004

所以写 0-4 正好覆盖周一到周五。周六周日不跑（A股休市）。

两个已知特性，不是故障：
① GitHub 的定时任务在整点高峰会排队，实际执行常在 7:00–7:20 之间，不会准点到秒。
② 仓库连续 60 天没有任何提交，GitHub 会自动停用定时任务。我们每天都会提交一份报告，所以不会触发。

出问题怎么查

症状原因与处理
Actions 里没有这个工作流最常见的问题：.github、src、docs 这些文件夹根本没上传成功，仓库里只有几个零散文件。网页拖拽上传看不见以点开头的文件夹，一定会漏。必须用 GitHub Desktop 上传，或在 Finder 里按 Cmd+Shift+. 显示隐藏文件后再拖。
Pages 构建失败（Build with Jekyll 报错）Pages 设的是「从 /docs 目录发布」，但仓库里没有 docs 文件夹。把 docs/ 传上去就会自动恢复。
跑了但微信没收到看 Actions 日志最后一步「推送到个人微信」：显示 401/403 是 SendKey 错了；显示 timeout 是网络问题，重跑一次多半就好。
微信里点链接 404三种可能：Pages 没开、文件夹没选 /docs、PAGES_BASE 结尾多了斜杠或少了仓库名。
报告顶部有黄色警告「数据异常」某天数据源挂了，报告仍会发出来但会明确标注，不会拿过期数据冒充当天的。
某一年显示「数据缺失」单个数据源临时失败，其他内容不受影响。这是有意设计的：宁可缺一格，不编一个数。
想换个时间跑改 .github/workflows/daily.yml 里的 cron。北京时间 = UTC + 8，比如晚 8 点就是 0 12 * * 1-5。

不想装 GitHub Desktop 的话

本机已经装好 git（2.54.0），可以在「终端」里用三条命令完成上传。需要先在 GitHub 生成一个访问令牌（Password Token），因为现在不能用账号密码推送。

生成令牌：GitHub 右上头像 → Settings → 左栏最下 Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic) → Note 随便填，Expiration 选 90 days，勾选 repo 那一整行 → 生成后立刻复制（只显示一次）。

然后在终端里：

# 进入项目文件夹（把路径换成你实际的 cloud 路径）
cd /Users/Mao/WorkBuddy/2026-09-29-22-49-27/cloud

git init -b main
git add .
git commit -m "init"
git remote add origin https://github.com/你的用户名/im-daily.git
git push -u origin main

推送时会要求输入用户名和密码：用户名填 GitHub 用户名，密码粘贴刚才那个令牌（不是账号密码）。
